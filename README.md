# dsh-memory-hub

DeepSeek Harness（DSH）的长期记忆中枢：**文件原生、用户掌控、人类批准写入**。

> 让 DSH 记住项目里值得留下的结论：可检索、可追溯、可干预。

## 当前状态

**设计完成，代码尚未开始。** V0.1 设计基于本机 DSH Desktop Runtime `0.2.1-rc.5` 的实测扩展点；实现前需先完成 Phase 0 宿主验证。本仓库暂不提供可安装的插件包。

- [完整设计](docs/DESIGN.md) —— 范围、架构、宿主契约、数据模型、一致性、门禁、审批、汇总、测试
- [知识文件格式](docs/KNOWLEDGE-FORMAT.md) —— frontmatter、状态、版本、示例

## 它是什么

一条知识是一个带 YAML frontmatter 的 Markdown 文件，放在用户目录下的 Hub 里。插件做四件事：

1. **自动预检**：每个用户回合开始时，用确定性检索找出当前项目/全局的相关知识，注入一份紧凑索引（ID、标题、一句话结论），不注入正文。
2. **按需读取与引用**：模型用 `memory_get` 读全文，用 `memory_cite` 记录"实际用了哪条、哪个版本"。
3. **候选 + 审批**：模型只能写候选（`pending/`）；提交为权威知识必须经过 DSH 原生人工审批，模型没有可伪造的批准令牌。
4. **收尾与汇总**：任务关闭必须给出回写评估（允许"没有新知识"）；管理员可手动把项目知识晋升为全局候选。

核心设计决定：

- **一个 Hub，多个作用域**（`global` / `domain` / `project`），没有多存储同步。
- **Markdown 是权威数据**，JSONL 是任务账本，索引可随时重建；V0.1 无 SQLite、无向量库、无后台模型调用。
- **任务 = 一个用户回合**，幂等键 `(sessionId, turn)`。
- **写入失败关闭**：无审批应答者时提交被拒绝，候选留在 pending。

## V0.1 范围

| 做 | 不做 |
| --- | --- |
| 单 Hub + N 个工作区、九类知识 | Web UI / 侧边栏面板 |
| 关键词检索、读取、引用 | 向量检索 / Embedding / 图数据库 |
| 回合预检与紧凑注入 | 自动扫描历史会话 |
| 变更工具门禁（可配置） | 后台定时巩固、自动总结 |
| 候选、审批、提交、废弃 | 云同步、多端双向同步 |
| 关闭评估、手动汇总 | 技能系统、多 Agent 编排 |
