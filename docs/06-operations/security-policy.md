# Security Policy

## 数据主权

- 记忆文件归用户所有，位于用户目录下。
- 插件不修改 DSH 核心、不写 profile 内部状态。
- 卸载插件保留记忆文件。

## 网络

- 插件运行时**不发送网络请求**。
- 面板通过 Host 回环路由读取数据。

## 审批边界

- `memory_commit` 必须经过 DSH 原生人工审批。
- 模型参数中没有可伪造的批准令牌。
- 面板只读，不提供批准按钮。

## 夜间维护边界

- 维护只写 `reports/` 与可选的 `pending/`，不写 `knowledge/`，不调用 `memory_commit`。
- 手动维护要求 admin 工作区；定时器由 Host 内部运行，但同样不 commit。
- 报告包含知识标题、摘要、作用域和问题描述，属于本地可读数据；不要把报告提交到公开仓库（`reports/` 已 gitignore）。
- 维护不做语义合并、不删除、不改写正文。

## 路径与作用域

- 路径经过规范化、真实化、大小写归一。
- 项目知识不会自动晋升到 global。
- `memory_get` 校验可见性。
- 模型无法通过参数扩大可见范围。

## 单写者

- 文件锁防止并发写。
- 第二个进程降级为只读。

## 敏感信息

- 不要在知识正文中粘贴密钥、令牌、完整生产日志。
- `source_refs` 只记录路径或事件区间。

## 报告安全问题

请通过 GitHub Issues 报告，不要公开披露漏洞细节。
