# Security Policy

## 数据主权

- 记忆文件归用户所有，位于用户目录下。
- 插件不修改 DSH 核心、不写 profile 内部状态。
- 卸载插件保留记忆文件。

## 网络

- 插件运行时**不发送网络请求**。
- 面板通过 Host 回环路由读取数据。

## 审批边界

- `memory_commit` 在会话内必须经过 DSH 原生人工审批。
- 模型参数中没有可伪造的批准令牌。
- 面板「待审批」允许人工点击批准/拒绝（V0.3.0 起），并支持勾选后批量批准/拒绝（V0.4.0 起，单次最多 50 条并返回逐条结果）：请求必须来自回环地址、带 `x-dmh-review: 1` 头、且 Origin 为本地地址；账本 `approvalRef` 记为 `panel:human`。配置 `policy.panel.review: false` 可关闭面板审核、恢复只读。
- 面板不提供批量编辑正文、重写或删除知识的端点；审核的批量操作只作用于已有 `pending/` 候选的状态。
- 已知边界：回环 HTTP 无法从技术上区分“人点击”和“本机脚本调用”；不要在本机运行不可信脚本的情况下依赖面板审核作为唯一防线。

## 夜间维护边界

- 维护只写 `reports/` 与可选的 `pending/`，不写 `knowledge/`，不调用 `memory_commit`。
- 手动维护要求 admin 工作区；定时器由 Host 内部运行，但同样不 commit。
- 报告包含知识标题、摘要、作用域和问题描述，属于本地可读数据；不要把报告提交到公开仓库（`reports/` 已 gitignore）。
- 维护不做语义合并、不删除、不改写正文。

## 定时蒸馏边界

- 定时蒸馏通过 Host `schedule` 服务注册每日任务（V0.5.0 起），到点由新会话或指定会话执行；任务本身不持有审批权限。
- 蒸馏提示词只调用 `memory_propose`（或顶端用 `memory_consolidate`），**禁止** `memory_commit`；候选仍需人工在面板批准。
- 新建会话的 `cwd` 固定为工作区 `root`，不跨越工作区；`target: session` 的会话必须存在且不是委派子会话。
- 任务标题以 `memory-hub:distill:` 为前缀，插件只增删改自己前缀下的任务；卸载插件不会删除已注册任务，需要用户自行清理。
- V0.6.0 的 `GET /dsh-memory-hub/api/sessions` 只读、仅回环，只返回会话 id、cwd、标题、更新时间与空会话标记；不含消息正文，且排除委派子会话。服务缺失或超时返回 `unavailable`，不影响其他端点。

## 路径与作用域

- 路径经过规范化、真实化、大小写归一。
- 项目知识不会自动晋升到 global。
- `memory_get` 校验可见性。
- 模型无法通过参数扩大可见范围。

## 写锁

- 每个 hub 根目录一把文件锁，防止同一份数据被并发写。
- 锁被占用只让**该根**降级为只读，不影响其他工作区根；只有显式 `readOnly: true` 是全局只读。
- 跨机拷贝来的锁（`host` 不符）视为失效；本机活进程的锁不自动抢占，避免出现两个写者。
- 配置写入（`config.yaml`）是原子替换，不依赖写锁，因此锁占用不会把用户锁在修复表单之外。

## 敏感信息

- 不要在知识正文中粘贴密钥、令牌、完整生产日志。
- `source_refs` 只记录路径或事件区间。

## 报告安全问题

请通过 GitHub Issues 报告，不要公开披露漏洞细节。
